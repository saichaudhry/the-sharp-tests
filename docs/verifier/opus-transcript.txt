⏺ All 32 tests pass now. I changed the code, not the test.

  The bug: yesPrice in api/_lib/pricing.js:18 checked ask - bid <= 0.05 using
  ordinary decimal math, which isn't exact in JavaScript. For a bid of 0.47 and
  an ask of 0.52, ask - bid comes out as 0.05000000000000004. That fails the <=
  0.05 check, so a spread of exactly 5¢ got the midpoint (0.495) when the rule
  says it should pay the ask (0.52). The test was right: it matches the rule in
  the code comment and in prompt_log.md.

  The fix: the spread is now converted to whole ten-thousandths of a dollar
  (Math.round((ask - bid) * 10000)) and compared against 500. Kalshi prices have
  four decimal places, so this comparison is exact. A spread just over 5¢, like
  5.5¢, still counts as wide.

  I tried a few other exact-5¢ spreads (0.10/0.15, 0.90/0.95, 0.01/0.06) and all
  of them now pay the ask. I haven't committed the change; tell me if you want
  it committed and pushed so CI runs.
